🔴 Thread #1: SIMULATION (100 Hz)

Role: THE WORLD

Rate: 100 Hz (10 ms per tick)

What it does:

  • ✓ Reads control commands from Shared<Control>
  • ✓ Updates ego vehicle kinematics
  • ✓ Updates traffic vehicles with toy ACC
  • ✓ Detects crashes
  • ✓ Counts laps
  • Owns: The only writer to World state

Lock acquired: std::unique_lock on world.mtx_ when calling step()

Other threads see: Snapshots (copies), not live state

🟠 Threads #2-4: SENSORS (Multiple Rates)

Role: PERCEPTION

Sensor Rate Reading Output
Radar 20 Hz (50 ms) Range, bearing, Doppler RadarReturn
Camera 15 Hz (67 ms) Bearing, est. range CameraBox
Lidar 10 Hz (100 ms) 2D point cloud LidarCluster

What they do:

  • ✓ Call world.snapshot() (lock-free read, only physics copy)
  • ✓ Simulate sensor physics + noise
  • ✓ Push measurements to BlockingQueue<SensorFrame>

Synchronization: std::shared_lock when reading world snapshot

🟢 Thread #5: FUSION (Event-Driven)

Role: MULTI-SENSOR FUSION

Rate: Event-driven (wakes when detections arrive)

Algorithm:

  1. Wait on queue.drain(20ms) → blocks until sensor frames arrive OR timeout
  2. Call tracker.predict_to(now) → Kalman predict step
  3. Convert raw measurements → world-frame Detections
  4. Call tracker.update(detections) → Kalman update step + data association
  5. Publish FusedPicture to Latest<FusedPicture>

Locks:

  • 🔒 Acquires BlockingQueue lock when draining
  • 🔒 Acquires Latest<> lock when publishing

🔵 Thread #6: PLANNER (10 Hz)

Role: PATH PLANNING

Rate: 10 Hz (100 ms)

What it does:

  • ✓ Lock-free check: if (picture.version() == 0) return; (wait for first fusion)
  • ✓ Read Latest<FusedPicture>
  • ✓ Run lattice planner: generate 5 candidate paths, score vs predicted obstacles
  • ✓ Write lowest-cost path to Shared<Path>

Locks:

  • 🔒 shared_lock when reading Latest<>
  • 🔒 scoped_lock when writing Shared<Path>

🟣 Thread #7: CONTROLLER (50 Hz)

Role: VEHICLE CONTROL

Rate: 50 Hz (20 ms)

What it does:

  • ✓ Lock-free check: if (picture.version() == 0) return;
  • ✓ Read Latest<FusedPicture> (ego pose, speed)
  • ✓ Read Shared<Path> (waypoints, target speed)
  • ✓ Run pure pursuit (steering) + PID (speed)
  • ✓ Write Control (accel, steer) to Shared<Control>

Locks:

  • 🔒 shared_lock when reading Latest<>
  • 🔒 scoped_lock when reading/writing Shared<>

🟡 Thread #8: RENDERER (12 Hz)

Role: VISUALIZATION (read-only)

Rate: 12 Hz (83 ms)

What it does:

  • ✓ Read everything (World snapshot, FusedPicture, Path, Stats)
  • ✓ Draw to terminal via ANSI escape codes
  • ✓ (Optional) Record JSON to file
  • ✓ Never writes to shared state

Locks: Acquires locks for reading, but no contention since never writes

⚪ Main Thread: REFEREE

What it does:

  • ✓ Spawns 8 worker threads using std::jthread
  • ✓ Waits on std::latch start_gate{8} → ensures all threads ready before any runs
  • ✓ Sleeps in a loop, checking: interrupted (Ctrl+C)? crashed? deadline reached?
  • ✓ Calls t.request_stop() on each thread (cooperative shutdown)
  • ✓ Waits for threads to join (automatic via jthread destructor)
  • ✓ Prints summary stats

🔐 Communication Channels Summary

1. BlockingQueue<SensorFrame>

Pattern: Many producers → One consumer

  • 🔒 Mutex + std::condition_variable
  • Producers: Radar (20 Hz), Camera (15 Hz), Lidar (10 Hz)
  • Consumer: Fusion thread
  • Synchronization: CV notify_one() wakes fusion when frames arrive
2. Latest<FusedPicture>

Pattern: One writer → Many readers

  • 🔒 Shared mutex + atomic version counter
  • Writer: Fusion thread
  • Readers: Planner (10 Hz), Controller (50 Hz), Renderer (12 Hz)
  • Optimization: Lock-free version() check avoids readers waking before data exists
3. Shared<Path>

Pattern: One writer → One reader

  • 🔒 Mutex (simple box)
  • Writer: Planner (10 Hz)
  • Reader: Controller (50 Hz)
  • Use case: Planner runs slower; controller reads latest plan repeatedly
4. Shared<Control>

Pattern: One writer → One reader

  • 🔒 Mutex
  • Writer: Controller (50 Hz)
  • Reader: World/Sim (100 Hz)
  • Use case: Sim reads latest control command every tick

⚡ Lock-Free Optimization: Version Counter

// In Latest<T>
std::atomic<std::uint64_t> version_;

// Planner/Controller before accessing picture:
if (picture.version() == 0) return;  // ← No lock!

// This is atomic with memory_order_acquire, so:
// ✓ Super fast (single CPU instruction)
// ✓ No mutex contention
// ✓ Safe: memory_order_acquire guarantees we see the published data
// ✓ Use case: avoid processing before first fusion cycle

🎯 Key Insights

  • No mutual blocking: Each thread runs at its own rate. If planner (10 Hz) is slow, controller (50 Hz) just reads stale Path—no deadlock.
  • Snapshot = thread safety: World::snapshot() returns a copy, so readers never race the writer.
  • Lock-free handshakes: picture.version() and game_over.load() are atomic—zero-contention checks.
  • Cooperative shutdown: std::jthread + std::stop_token allows clean stopping without forceful termination.
  • std::latch synchronization: start_gate ensures all threads are ready before any runs—avoids early-startup races.
